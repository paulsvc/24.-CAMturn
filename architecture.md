## 2. Core Technical Strategy: The 3-Layer Hybrid CAM Pipeline

All turning operations must flow through a strict 3-layer architecture to prevent tool gouging and emit valid LinuxCNC G-code:

### Layer 1: Geometric Pre-Clipping ("Shadowing") via `Shapely`
`LibLathe` does not fully model physical insert holder clearances on steep undercuts. Before passing a 2D $(X, Z)$ profile from STEP or DXF into `LibLathe`:
- Pass the raw $(X, Z)$ profile through `src/lathecam/cad/shadowing.py`.
- Use `shapely` to compute the "reachable silhouette" based on the active tool's **Lead Angle** and **Trailing Clearance Angle**.
- Bridge over any undercut or groove that exceeds the tool's clearance cone so `LibLathe` never generates a heel-gouging path.

### Layer 2: Dual-Path Operation Solver (`src/lathecam/cam/`)
Divide machining operations into two distinct execution engines that both output a standardized list of internal `MotionCommand` objects:

1. **LibLathe-Backed Operations (`engine.py`):**
   - **Facing (`FaceOP`):** Planar stock removal on $Z$.
   - **Roughing (`RoughOP`):** Unrolled step-down passes. (We use unrolled passes rather than LinuxCNC `G71` so the 3D viewport can accurately render intermediate passes and compute cycle time).
   - **Profiling (`ProfileOP`):** Continuous finishing path along the shadowed profile.
   - *Important:* `LibLathe` always calculates in **Radius Mode** (`X` = radius). Keep all internal coordinates in Radius Mode until Post-Processing.

2. **Native Parametric Operations (`operations.py`):**
   - **Threading (`ThreadingOp`):** Emits either a single-line LinuxCNC **`G76`** cycle (`G76 P- Z- I- J- K- R- Q- H- E- L-`) for post-processing AND an unrolled `G33` preview path (using $\sqrt{n}$ constant chip-area depth degression and $29.5^\circ$ flank infeed) for 3D viewport rendering.
   - **Peck Parting & Grooving (`PartingOp`):** Replaces `LibLathe`'s naive single-plunge `PartOP`. Implements radial pecking along $X$ (`G1` plunge -> `G0` retract by `0.5mm` to break the chip) and optional corner chamfers.
   - **Axial Drilling (`DrillingOp`):** Locks turret at `X0.0`, forces RPM spindle mode (`G97`), and emits `G83` (peck drilling) or `G73` (chip-break drilling) along the $Z$-axis.

### Layer 3: Strict LinuxCNC Lathe Post-Processor (`src/lathecam/post/linuxcnc.py`)
Translate internal `MotionCommand` lists and parametric cycles into LinuxCNC-compliant `.ngc` files according to `linuxcnc.org/docs/html/gcode/g-code.html`:

- **Mandatory Preamble:**
  ```gcode
  %
  (Generated by LatheCAM for LinuxCNC)
  G18 G21 G40 G49 G80 G90 G95 G7
  ```
  *(Note: `G18` = ZX Plane, `G21` = Metric, `G95` = Feed/Rev, `G7` = Diameter Mode).*
- **Tool Change Protocol:**
  LinuxCNC requires `G43` immediately after `M6` to load the lathe tool table $X/Z$ offsets:
  ```gcode
  M6 T{tool_number} G43
  ```
- **Spindle Control (CSS vs. RPM):**
  - Turning/Facing/Parting: Use Constant Surface Speed (`G96`) with LinuxCNC's `D` word for max RPM clamp (NEVER use Fanuc `G50`):
    ```gcode
    G96 D{max_rpm} S{surface_speed_m_min} M3
    ```
  - Drilling/Threading: Switch to constant RPM mode (`G97`) so spindle index synchronization remains stable:
    ```gcode
    G97 S{rpm} M3
    ```
- **The `G7` Diameter vs. `G18` Arc (`I`/`K`) Rule (CRITICAL):**
  - When outputting in `G7` (Diameter Mode), multiply all `X` coordinates from `LibLathe` by **`2.0`**.
  - **NEVER multiply `I` or `K` by `2.0`.** In LinuxCNC `G18` (`G2`/`G3`), incremental center offsets `I` (X-offset) and `K` (Z-offset) are **strictly radius/distance values**, even when `G7` Diameter Mode is active.
  - Ensure `G2`/`G3` rotation direction matches standard LinuxCNC rear/front toolpost conventions in `G18`.

## 4. Coding Conventions & Quality Bar
- **Type Hints:** Mandatory across all functions (`from __future__ import annotations`).
- **Coordinate System:** Internally, all profiles and `LibLathe` points are stored as `(x_radius, z_axial)` in millimeters (`float`), where `Z = 0.0` is the front face of the finished part and `Z < 0.0` extends toward the chuck.
- **Error Handling:** Never crash the Qt event loop on invalid CAD topology or impossible tool clearances; catch exceptions in the CAM worker and display a clear warning badge on the operation node in the Feature Tree.
